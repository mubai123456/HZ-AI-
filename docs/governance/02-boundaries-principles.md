# 边界与原则

## 前提

本文件用于约束后续治理与分层重构的决策方式。当前工作区为脏工作区，实施时不得覆盖无关改动，不得在缺少文档和阶段确认的前提下随意扩大范围。

## 一、业务边界

### 受保护业务层

以下内容属于受保护业务层，默认不在 UI 治理阶段直接重写：

- AI 应用定义、任务提交、结果展示
- 素材大厅的数据规则、领取规则、下载规则
- Feishu 同步、回填和映射处理
- RunningHub 的请求、轮询、回调与任务关联

### 允许调整的业务外围

- 页面入口组织方式
- 页面标题体系与展示顺序
- 设置页归类方式
- 读取配置的适配层
- 非敏感配置的管理入口

## 二、设计边界

### 属于模板问题的判断规则

满足以下特征时，优先归类为模板问题：

- 多个页面都出现相似的页头、操作区、筛选区、内容区结构
- 同类页面之间只是业务数据不同，布局骨架却重复实现
- 标题、空态、加载态、错误态表现不一致

### 属于视觉系统问题的判断规则

满足以下特征时，优先归类为视觉系统问题：

- 相同语义的按钮、表单、卡片、状态提示样式不同
- 同站点页面之间间距、圆角、字阶和容器层级不统一
- 同一种交互动作在不同页面采用不同承载方式

### 当前设计层允许做的事

- 统一壳层和导航分层
- 建立标准页面模板
- 建立标准页头、过滤条、工具栏、模态框、空态和反馈组件

### 当前设计层禁止做的事

- 借视觉治理之名改变业务语义
- 为了统一 UI 直接改写已有服务层规则

## 三、配置边界

### 可以进入配置中心的内容

- 网站名称、标题模板、品牌文案
- 导航分组名称和部分可运营文案
- RunningHub、Feishu 的非敏感目标参数
- 站点级行为开关与默认值

### 暂不进入后台明文配置的内容

- `RUNNINGHUB_API_KEY`
- `FEISHU_APP_SECRET`
- `JWT_SECRET`
- 其他直接影响安全边界的敏感密钥

### 配置原则

- 先定义“什么可配、什么不可配”，再做配置实现
- 先建立读取优先级和回退策略，再做后台表单
- 配置中心不得先吞并敏感密钥管理

## 四、文档边界

### 文档必须先于实现

- 没有 Phase 文档或边界确认，不进入实现
- 没有模板规范，不允许大面积改页面
- 没有验证基线，不允许宣布阶段完成

### 文档必须回答的问题

- 为什么改
- 改哪些层
- 不改哪些层
- 如何验证没伤到核心业务

## 五、决策原则

- 先分层，再改动
- 先模板，再页面
- 先配置边界，再配置实现
- 先统一高频交互，再做局部润色
- 先保护核心业务，再推进界面重构

## 六、范围判定清单

### 如果一个问题属于模板层

- 通过共享页面骨架或共享结构组件解决

### 如果一个问题属于业务层

- 通过服务层、数据层或接口层治理解决
- 不应在纯 UI 重构阶段偷偷改掉

### 如果一个问题属于配置层

- 先定义配置模型、优先级和权限边界
- 再决定是环境变量、数据库设置还是只读展示

## 七、阶段纪律

- UI 重构不得顺手改业务服务
- 配置中心不得先吞并敏感密钥管理
- 当前工作区是脏工作区，实施期间不得覆盖无关改动
- 没有通过验证基线的阶段不能标记完成
