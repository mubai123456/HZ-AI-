# 当前状态审计

## 审计范围

本审计基于当前仓库现状，只记录已经存在的问题与证据，不提前展开未来 UI 方案细节。

当前工作区为脏工作区，仓库内存在与本计划无关的历史改动。本文只把这些改动视为实施风险背景，不把它们本身当作治理对象。

## 审计结论

当前网站的主要问题不是“某个页面难看”，而是以下几类系统性问题叠加：

- 导航结构平铺，用户侧与管理侧心智没有清晰分层
- 页面模板没有形成统一约束，不同页面各自长出不同骨架
- 工作台布局实现重复，核心高频页缺少统一壳层
- 品牌与集成配置分散在环境变量、页面常量和局部后台入口里
- 后台交互仍混用浏览器原生弹窗和各类局部写法，专业感不足
- 已有组件复用主要停留在基础块级别，没有形成真正的页面模板层

## 事实证据

### 1. 导航平铺

- `src/lib/navigation.ts`
  - `ADMIN` 角色直接返回 `baseNavigation + adminNavigation`
  - 管理员看到的是普通导航和后台导航的顺序拼接，而不是分组导航
- `src/components/workbench-shell.tsx`
  - 导航渲染直接遍历单个 `navigation` 数组，没有分区结构
  - 桌面端和移动端导航都沿用同一套扁平模型

影响：

- 管理员的信息负担偏高
- 站点无法表达“用户侧入口”和“后台入口”的层级关系

优先级：`P0`

### 2. 页面模板不统一

- `src/components/page-header.tsx`
  - 已有通用 `PageHeader`
- `src/app/(workspace)/apps/page.tsx`
  - 已引入 `PageHeader`，但页面实际未使用，直接渲染 `AppMarketplace`
- `src/components/app-marketplace.tsx`
  - 组件内部自己生成二级标题和局部筛选头部，说明页面头部职责下沉到内容组件
- `src/components/workbench-shell.tsx`
  - 顶部壳层又单独渲染一个全局 `h1`

影响：

- 站点存在全局壳层标题、页面标题、局部内容标题并存的问题
- 用户难以快速理解当前所处层级

优先级：`P0`

### 3. 工作台骨架重复

- `src/components/workbench-layout.tsx`
  - 一套三栏布局，固定 `35% / flex / 15%`
- `src/components/three-column-layout.tsx`
  - 另一套近似三栏布局，固定 `30% / flex / 10%`
- 两者都依赖 `h-[calc(100vh-8rem)]` 和本地折叠逻辑

影响：

- 高优先级页面的骨架能力分叉
- 后续改响应式策略、标题区、折叠策略时需要双份维护

优先级：`P0`

### 4. 配置分散

- `src/lib/env.ts`
  - 已有 `APP_NAME`、RunningHub、Feishu 等环境变量入口
- `src/app/layout.tsx`
  - 站点 `metadata.title` 和 `description` 仍是写死值
- `src/components/workbench-shell.tsx`
  - 侧边栏品牌文案和标题仍是组件内写死
- `src/app/(workspace)/admin/settings/feishu/page.tsx`
  - Feishu 目标表与字段映射已有单独后台入口
- `src/app/api/internal/admin/settings/feishu/route.ts`
  - Feishu 设置已形成数据库配置 + env 兜底的局部模式

影响：

- 同类配置没有统一归口
- “品牌配置”和“集成配置”处于不同成熟度状态

优先级：`P1`

### 5. 后台交互仍偏原始

- `src/components/admin-apps-client.tsx`
  - 列表页内仍使用 `window.confirm`、`window.prompt`
  - 单条删除、批量改分类、批量改标签依赖原生浏览器弹窗

影响：

- 后台体验不统一
- 缺少标准确认流程、输入校验体验和一致的错误提示承载层

优先级：`P1`

### 6. 复用层级不足

- 当前仓库已具备壳层、卡片、页头等基础复用能力
- 但仍缺少页面模板层，例如：
  - 列表页模板
  - 编辑页模板
  - 设置页模板
  - 统一 `Workbench` 模板

影响：

- 新功能虽然不是完全从零开始，但依然容易“各写各的”
- 网站整体观感会随着功能增长继续分裂

优先级：`P1`

### 7. 应用中心过滤与状态管理不成熟

- `src/components/app-marketplace.tsx`
  - 分类筛选保存在局部 `useState`
  - 排序和时间筛选下拉框目前没有真正接线
- `src/app/(workspace)/apps/page.tsx`
  - 页面只承担数据读取，交互状态未进入 URL 层

影响：

- 刷新、分享、返回恢复体验不完整
- 看起来像“已规划但未收口”的页面

优先级：`P2`

## 看似可合并、当前先不动的范围

- `AI 应用`、`素材大厅`、`Feishu 同步`、`RunningHub 集成` 在信息架构上可以重新组织，但当前不应先改它们的服务层实现
- 各后台批量接口已经在推进统一化，当前优先把页面模板和交互标准定清楚，不直接重写现有 bulk 路由
- Feishu 设置已经有局部配置后台，当前应先抽象配置边界，而不是立刻把所有第三方配置全部搬到一个大设置页

## 优先级汇总

- `P0`
  - 导航平铺
  - 页面模板不统一
  - 工作台骨架重复
- `P1`
  - 配置分散
  - 后台交互原始
  - 复用层级不足
- `P2`
  - 应用中心过滤状态与页面收口不完整

## 本阶段结论

这次治理应优先从壳层、模板层、配置边界和交互层入手，而不是直接动核心业务服务。只有先把“网站怎么长”这件事约束住，后续新增功能才不会继续堆出新的结构分叉。
