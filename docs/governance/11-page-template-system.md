# 页面模板体系

## 文档目标

本文件定义 `AI Workbench` 后续统一使用的页面模板体系。目标是让新页面不再“自己长结构”，而是先归属模板，再填入业务内容。

当前工作区为脏工作区。本文为设计规范，不包含页面实现改动。

## 模板设计原则

- 一个页面只能归属一个主模板
- 模板负责顶层结构，业务组件负责填充内容
- 标题、筛选、工具栏、空态、错误态必须由模板层统一承载
- 模板必须有桌面端与移动端退化策略

## 模板总览

### 1. Dashboard 模板

适用页面：

- `/`
- `/admin`

结构：

- 页面头部
- 指标区
- 两栏或三栏重点区
- 可选的最近活动区

适合承载：

- 今日概览
- 快捷入口
- 异常提醒
- 最近活动

不适合承载：

- 大型编辑表单
- 高密度管理列表

### 2. Browse 模板

适用页面：

- `/apps`
- `/assets`
- `/profile` 中偏浏览型子区块

结构：

- 页面头部
- 过滤条
- 分类/标签导航
- 列表或网格主体
- 空态

适合承载：

- 应用发现
- 素材发现
- 个人资产浏览

不适合承载：

- 多步骤编辑
- 三栏工作台

### 3. Workbench 模板

适用页面：

- `/apps/[code]`

结构：

- 应用头部
- 左侧输入区
- 中央结果区
- 右侧历史/队列区

规则：

- 只允许一套统一工作台骨架
- 不允许继续并行维护多套三栏布局
- 桌面、平板、移动端都必须有明确退化策略

### 4. Management List 模板

适用页面：

- `/tasks`
- `/sync`
- `/admin/apps`
- `/admin/users`
- `/admin/materials`
- `/admin/prompt-templates`
- `/admin/categories`
- `/admin/banners`

结构：

- 页面头部
- 过滤条
- 批量工具栏
- 列表或表格主体
- 空态 / 错误态 / 批量反馈区

规则：

- 页面级标题必须由模板提供
- 列表内部不再自己重复生成主标题
- 危险操作统一走标准确认交互

### 5. Editor 模板

适用页面：

- `/admin/apps/new`
- `/admin/apps/[code]`

结构：

- 页面头部
- 表单分区
- 附属说明区
- 底部或顶部固定操作条

规则：

- 新建与编辑共用同一骨架
- 不允许每个编辑页自己发明容器与操作区结构

### 6. Settings 模板

适用页面：

- `/admin/settings/feishu`
- 后续站点设置、集成设置页面

结构：

- 页面头部
- 设置分组区块
- 保存反馈区
- 配置来源说明区

规则：

- 明确显示配置来源和生效范围
- 明确区分“后台可改项”和“仅状态展示项”

### 7. Detail Inspection 模板

适用页面：

- `/tasks/[id]`

结构：

- 页面头部
- 摘要指标区
- 主详情区
- 侧边日志或辅助信息区

规则：

- 该模板用于看执行结果和审计信息
- 不与 Workbench 模板混用

## 模板层级职责

### 模板层负责

- 页面头部
- 标准布局骨架
- 操作区位置
- 过滤条与工具栏承载位
- 空态、错误态、加载态位置

### 业务组件负责

- 数据请求和状态处理
- 列表项或表单项渲染
- 业务字段展示
- 领域交互逻辑

## 模板约束

### 禁止事项

- 内容组件直接输出页面主标题
- 同一模板类型出现多套顶层结构
- 为了兼容历史页继续保留长期并行骨架

### 必须事项

- 所有新页面在设计阶段先归类模板
- 复用模板时只允许扩展插槽，不允许复制一份改造

## 响应式基线

- `Dashboard`
  - 桌面：多列摘要 + 重点区
  - 移动：指标纵向堆叠
- `Browse`
  - 桌面：筛选条 + 网格/列表
  - 移动：筛选面板折叠为抽屉或横向 chips
- `Workbench`
  - 桌面：三栏
  - 平板：两栏 + 可切换侧栏
  - 移动：主内容优先，辅助面板抽屉化
- `Management List`
  - 桌面：工具栏 + 表格/卡片列表
  - 移动：筛选与批量工具折叠，列表切换为卡片优先
- `Editor`
  - 桌面：主编辑区 + 辅助区
  - 移动：单列分段式编辑
- `Settings`
  - 桌面与移动都保持分组块结构，但降低并列密度

## 进入 Phase 2 的模板前提

- `PageHeader` 需要提升为模板层标准接口，而不是“有些页用、有些页不用”
- `WorkbenchLayout` 与 `ThreeColumnLayout` 需要收敛为单一骨架能力
- 管理列表页需要统一抽象过滤条、工具栏和反馈区
